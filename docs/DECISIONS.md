# Design & technical decisions

Each entry: decision, reason, consequence. Source prompts are not modified; deviations are recorded here.

| ID | Decision | Reason | Consequence / follow-up |
|---|---|---|---|
| D-001 | Repository started empty → new Unity 2022.3 LTS 2D project created from scratch. | Audit found no existing code/assets (docs/AUDIT.md). | No migration risk; everything is new. |
| D-002 | Engine-free deterministic C# core (`Assets/Forgebound/Core`, asmdef `noEngineReferences`) compiled both by Unity and by `dotnet` (netstandard2.1, C# 9). | Headless tests, balance simulator and bots must use the *same* rules as the game (spec §11). Unity is not installed in this environment. | Presentation is a thin MonoBehaviour layer reading the event stream. |
| D-003 | Integer simulation: 30 ticks/s, milli-units, permille multipliers, xoshiro128** RNG with per-system streams. | Cross-platform determinism (replays, seeds, balance). | No floats in gameplay; replays verified by tests. |
| D-004 | Generated PNG/WAV committed directly (no Git LFS) while under budget (~11 MB art, ~8.5 MB audio). `.blend` stays LFS-tracked. | LFS upload through this environment's proxy is unverified. | Revisit LFS when art exceeds ~60 MB. |
| D-005 | Content authored as JSON in `Resources/Content` (with `//` comments) instead of ScriptableObjects. | Must load identically in Unity and headless tools; diff-friendly; validated by `ContentValidator`. Spec allows "robust validated structured files". | Editor content browser = Codex screen + `Forgebound/Validate Content` menu; a ScriptableObject importer can be added later without changing the runtime. |
| D-006 | Board links: the first "charging" relay on a path (Echo / Capacitor / Governor) decides the listened event + threshold; direct weapon→weapon ports form a "Resonance" link (OnHit, 4 charges, 50%). Proc attacks never charge links. | Makes every relay meaningful and guarantees no energy recirculation. | Documented in docs/COMBAT_RULES.md; tested. |
| D-007 | Modifier precedence Spawn → Split → Target → Pierce → Impact → Timing is enforced by compiling ops into independent fields (order-independent). | Spec §4 precedence; arbitrary combos stay defined. | `ModifierOrderDoesNotChangeCompiledSpec` test. |
| D-008 | Run = 3 chapters × 5 rows (15 steps) drawn from 5 biomes (2 for ch1, 2 for ch2, 1 for ch3). Second prompt mentions "5 chapters"; the first prompt's 20–30-minute 3-chapter run is kept, 5 biomes provide the 5 themes. | Run length target; 5 authored biomes still ship. | Endless/5-chapter mode can reuse the generator later. |
| D-009 | Cores: fire, frost, lightning, earth, life, shadow, venom, arcane, wind, steel, solar, void (merged list of both prompts). | Each enables a different build logic (status, chain, armour break, sustain, execute, DoT spread, echo, tempo, crit/bleed, mark, control). | Art pipeline updated to these ids. |
| D-010 | Built-in render pipeline + SpriteRenderer + uGUI built from code; URP 2D deferred. | URP asset/renderer setup can't be created or verified without the editor; runtime-built UI avoids hand-authored scene/prefab references that silently break. | Migration plan in docs/KNOWN_ISSUES.md (KI-03). |
| D-011 | Game auto-boots via `[RuntimeInitializeOnLoadMethod]` from an empty scene. | No scene/prefab GUID dependencies. | Build script creates `Boot.unity` automatically. |
| D-012 | Balance knobs in `tuning.json` (chapter enemy HP/damage, boss/elite, shield cap/decay, post-battle repair, leech cap, crit cap, projectile falloff). | Spec §11 tune knobs; one place, applied once in code. | Every change followed by `forgebound sim` vs baseline. |
| D-013 | Enemy DoT on the hero ticks once per second and caps at 3 stacks; non-reach melee deals 70% to flyers; ranged enemies target the Forgemaster over summons; hero shield capped at 50% max HP and decays 6%/s; +15% field repair after won battles. | Found by the simulator: Burn stacks killed heroes in seconds, flyers hard-countered melee, shields/summons made sustain dominant, attrition killed every non-sustain build. | Re-measured after each change (docs/BALANCE.md). |
| D-014 | Shop "temper" service (tier upgrade for gold +15 surcharge) added as a gold sink. | Bots/players accumulated unspendable gold once slots were full. | Economy only has Gold + Forge Essence (no new currency). |
| D-015 | Workshop isolation: an Adventure run reads only unlocked Forgemasters and an optional favourite recipe hint from the profile. | Spec: sandbox power must not leak into runs. | `SandboxNeverLeaksIntoAdventure` test. |
| D-016 | Board undo/redo implemented as logged actions with controller-side snapshots. | Keeps action-log replays deterministic. | `BoardUndoRedoIsReplaySafe` test. |
| D-017 | Procedural original audio (numpy synthesis) as the shipped baseline. | No licensed audio tools/assets available; provenance must be clean. | Needs sound-designer pass (KI-06). |
| D-018 | Legendaries change rules through a `LegendarySignature` (21 implemented behaviours) and/or innate runes; validator rejects pure-stat legendaries. | Spec: legendaries must alter behaviour, not only numbers. | 42 recipes, each tested in combat (`legendary_*` scenarios). |
| D-019 | Hints are stored in the profile as `hint:*` entries (shown once, disable-able). | Onboarding by doing without a scripted tutorial level. | A guided first-run tutorial is still listed as follow-up (KI-09). |
